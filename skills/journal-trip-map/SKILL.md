# Journal Trip Map — 英文竖版手帐地图生成器

把行程信息重排成一张**竖向、可单手滑动阅读**的手写/贴纸风地图页。核心价值：**信息密度高，但在手机小屏上仍然好读**。

> `<skill-directory>` 指本 skill 目录，不是用户的项目目录。

**铁律：不编造数据**。原文没有的（距离、时长、车次、店名）一律留 `{{占位}}` 或留空，并在最终回复里列出「待确认清单」。宁缺毋编。

---

## 1. 触发后第一步：补齐信息

所需最小信息集：

| 字段 | 说明 | 缺失时 |
|---|---|---|
| 行程标题 / 第几天 | 如 `X's Trip · Day N` | 用 `{{TRIP_TITLE}}` |
| 日期 | 一行写清星期 | 用 `{{DATE_LINE}}` |
| 城市（英 + 可选中文） | 用于页眉标签与地图题签 | 用 `{{CITY_EN}}` |
| 抵达方式 | 车次/航班 + 起终点 + 时间 | 留空并列入待确认 |
| 站点清单 | 名称 / 方位 / 停留 / 交通时长 | **至少要有，否则无法成图** |
| 站点间距离 | 用于地图上的里程气泡 | 不写气泡，不猜 |
| 住宿 & 离开方式 | 页脚信息 | 页脚留占位 |
| 是否保留中文对照 | 默认保留小号中文（方便打车/导航） | 用户可要求全英文 |

**抽取后先回一张站点表给用户核对**（名称 / 方位 / 时长），确认后再出图。若用户明确说"别问了直接做"，跳过核对但在回复里附上该表。

## 2. 制作流程

1. **读模板**：`<skill-directory>/templates/journal-map-portrait.html`
2. **替换占位符**：全部 `{{...}}` 一次性替换（禁止残留）
3. **调整地图布局**：见下方 §4 坐标规则；点位数增减时同步调整面板高度与虚线路径端点
4. **输出到 `/workspace/`**，文件名建议 `<slug>-journal-map.html`
5. **调用 present_files 预览**
6. **回复中标注 judgment call**：原文自相矛盾处（如两个不同车次、同一段两个时长）统一成哪个，必须写出来让用户确认

## 3. 版式与视觉规范（必须遵守）

### 页面结构（自上而下，单栏）

```
header card  →  标题 / 日期线 / 途经点汇总 / 标签
map card     →  竖版 SVG 主图
Today's Route → 编号步骤清单（与地图编号路钉一一对应）
Quick Orientation → N / E / C / SW 方位速读
Legend       → 图标与线型说明
footer strip → 抵达 + 离开的班次信息（深色条）
```

### 尺寸与可读

- `max-width: 470px`，居中；**禁止横向滚动**
- 正文 ≥ 13px，次要信息 ≥ 10.5px
- SVG `viewBox="0 0 400 580"`，`width:100%; height:auto`

### 字体

- 标题 / 数字 / 方位 chip：`'Caveat', cursive`（600/700）
- 正文与地图内文字：`'Patrick Hand', 'Comic Sans MS', system-ui, sans-serif`
- 通过 Google Fonts 引入，**必须有离线降级** font stack

### 色板

| Token | 色值 | 用途 |
|---|---|---|
| `--paper` | `#ece1c6` | 页面底色（牛皮纸） |
| `--card` | `#fffdf4` | 卡片 / 地图内的便利贴 |
| `--ink` | `#4a3b2f` | 描边与主文字（深棕，非纯黑） |
| `--line` | `#8a5a44` | 虚线路线、辅助文字 |
| `--mapbg` | `#d9e7ef` | 地图水域/底图 |
| `--red --gold --green --blue --plum` | `#e2574c #e8b64c #6fa06a #5b8fb9 #a06a9a` | 五类节点配色 |

### 手帐质感三件套

1. **手绘边**：`border-radius: 18px 225px 18px 255px / 255px 18px 225px 18px`，相邻卡片用 `alt` 类反向，避免呆板
2. **和纸胶带**：卡片顶部 `.tape`（半透明 + 虚线边 + ±4° 旋转）作为装饰
3. **贴纸感**：地图内信息框用白色圆角 + `feDropShadow` + 轻微 `rotate(±1~2deg)`

## 4. 地图 SVG 画法规则

### 默认布局（viewBox 0 0 400 580）

| 元素 | 位置 | 说明 |
|---|---|---|
| 底图圆角矩形 | `4,4 → 392×572` | `--mapbg` + ink 描边 |
| 道路 / 河流 | 曲线，`#c3d7e2` / `#b7d3e4` | 纯装饰，画在最底层 |
| 云朵 | 2–3 组白色椭圆 | 装饰 |
| 指南针 | 右上 `(358,46)` | 上北下南不可改 |
| 题签 | 左上 `(14,14)` | 城市名 + 中文小字 |
| 远点位（北端） | 顶部居中 `(120,26)` | 通常是最远那个点 |
| 门户点（车站/机场抵达） | 右侧中部 | 与抵达班次绑定 |
| 中转点 | 左中侧 | 可选 |
| 市中心聚集面板 | `(52,296)` | 多个近距离点合成一块清单 |
| 终点（住宿/离开） | 左下 `(26,468)` | 与住宿贴纸并排 |
| 地理说明框 | 右下 `(228,514)` | 虚线边框小注 |

### 元素增减算法

- 聚集面板高度 = `22 + 行数 × 17 + 6`；删一行就减 17px 高度并删对应 `<text>`
- 面板变矮后，**把下游虚线路径的起点 y 上移到面板底边**，避免线路悬空
- 相邻留白 ≥ 20px；新增信息框时优先放在现有元素的正下方，不要横向挤压
- 若点位数 ≤ 3，可删掉聚集面板，直接放三个独立贴纸框

### 路线与标注

- 主路线：**虚线** `stroke-dasharray="7 6"`，`--line` 色，宽 2.3，圆端点
- 里程/时长写成独立"气泡"（白色圆角 + 阴影），压在对应线段上，不要贴着节点
- **编号路钉 ①–⑤ 必须与下方 Today's Route 的编号严格一致**，颜色按 `--red → --gold → --green → --blue → --plum` 循环
- 图标统一用 emoji（地图内 `<text>` 即可）：🚉 车站 ✈️ 机场 📦 仓库/拜访点 🏢 商场/办公室 🎨 艺术点 🖼️ 画廊 ⛲ 地标 🌳 公园 🏨 住宿

### 交付前必查

- [ ] `egrep '\{\{'` **零残留**（未确认项除外，且已在回复中声明）
- [ ] 地图上无元素重叠、无文字溢出容器宽度
- [ ] 编号路钉 ↔ 步骤清单 完全对应
- [ ] 竖屏 375px 宽下无横向滚动
- [ ] 断网时字体降级仍可读

## 5. 语言规则（重要）

- **默认跟随用户语言**：用户说中文 → 全中文输出（标题、正文、地图内文字、图例、页脚全部中文，不夹英文句子）。
- 仅当用户明确要求「英文版 / bilingual」时，才正文用英文，并可在地名后附小号中文原名（方便当地导航）。
- 航班号、车次、确认码等编号不属于"语言"，保持原样。
- 反面教材：小屏（≤470px）上英文长句极易溢出贴纸框、显得杂乱——**手机端优先用中文短句**。

## 5.5 多日行程适配（>1 天）

单日行程用「门户→远点→中点→聚集→终点」五节点路线；**多日行程（N 天）改为三段式**：

1. **总览动线图**：竖版「地铁图」式布局——一条纵贯主线 + 左右支线；节点只用 ≤6 字短标签（中文场景下尤其要短）；气泡只标关键车程；日编号圆钉与下方日卡一一对应
2. **主题策略块**：把行程的灵魂提炼成 4 格（如高反行程的「低进/峰值/下撤/缓出」，商务行程的「拜访/会议/差旅/复盘」）
3. **每日卡片**：D0–DN，每卡 ≤3 行：交通 badge + 住宿/海拔 + 核心行程一句 + 一条最关键提示（⚠️ 红色突出）

原文串行/错位的贴士，按行程逻辑归位并在交付说明中标注；住宿列写了非住宿信息（如航班）的，不写死，列入待确认。

## 7. 迭代偏好（来自使用习惯）

- 用户以「截图 + 截图」迭代：**先对齐原作风味**（色系、线型、区块），再改细节
- 用户偏好去掉冗余标签、保留核心节点：删点位时要**同步删除所有连带引用**（标题汇总、步骤、方位说明、图例），不要留孤立描述
- 小改动直接改文件并在回复里给「改动位置表」，不要整篇重生成
- 主动标记原文中的前后矛盾（不同车次、同一段两个时长），给出统一建议并等待确认
